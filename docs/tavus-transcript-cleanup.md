# Tavus 최종 전사와 종료 정리

## 수정한 결함

Renderer Worker는 정상 종료를 확인한 뒤 `providerConversationId`와
`fullPipeline`을 지웠지만, 최종 전사 조회는 지워진 `providerConversationId`만 사용했습니다.
따라서 정상적으로 대화하고 종료해도 `unavailable`을 반환할 수 있었습니다.

종료 이후에는 기존 JSON 저장소의 `fullPipeline.transcriptConversationId`에
서버 전용 전사 조회 식별자만 보존합니다. 활성 리소스 식별자는 기존대로 비워
종료된 세션이 계속 재수거되거나 신규 생성 차단에 남지 않게 합니다.
PAL 정리가 지연되면 PAL 식별자와 전사 식별자를 함께 유지하고, 이후 정리에서도
전사 식별자는 유지합니다.

미디어 토큰·Daily URL·프롬프트·시나리오·음성은 보존하지 않습니다.
소유자·tenant·파이프라인·종료 상태 검사와 제공자 응답의 대화 ID 대조는 유지합니다.
공개 세션 응답에 내부 식별자를 추가하지 않으며 DB 컬럼 변경도 없습니다.
Anam의 기록 처리와 기존 사용자 동의는 변경하지 않습니다.

## 적용과 한계

API와 Renderer Worker의 새 빌드를 별도 승인 후 게시해야 합니다.
앱은 확정 전사를 가져와 저장하고 피드백 작업이 접수된 다음 리포트 화면으로 이동합니다.
이 수정은 제공자 전사 자체의 지연·만료·비활성화를 해결하지 않습니다.

이미 모든 대화 ID가 지워진 과거 세션은 이 코드만으로 복구되지 않습니다.
과거 대화 복구는 별도 승인된 제공자 기록 대조가 필요하며, 브라우저 임시 자막이나
다른 세션의 기록을 최종 전사로 대체해서는 안 됩니다.
