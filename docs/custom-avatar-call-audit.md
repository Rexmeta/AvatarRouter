# 커스텀 생성 시도별 호출 감사

## 목적

같은 자산의 과거 실패와 새 요청을 섞지 않고, **각 Worker 생성 시도에서
애플리케이션이 시작한 호출 수와 중단 지점**을 구분하기 위한 구조화 로그와
최소 내구성 원장이다. HTTP 거절 사유 전달, 제공자 자원 복구, 과금 내역 조회와는 별개다.

## 연결 키와 기록

운영 로그는 `service: provisioning_audit` 항목을 사용한다. DB 원장은
`provisioning_attempts`의 시도별 단일 상태 스냅샷으로 다음 필드만 보존한다.

- `assetId`: 동일 자산의 작업 이력을 연결한다.
- `attemptId`: Worker가 작업을 수행할 때 새로 발급하는 임의 UUID.
  명시적 재요청은 서로 다른 시도다.
- `sourceBuildId`: API·Worker 상태 응답에서 사용하는 것과 같은 소스 지문.
  번들 없는 단위 검사에서는 `unbundled`다.
- `state`: `active`, `finished`, `result_unknown`.
- `sequence`, `elapsedMs`: 마지막 상태의 순서와 경과 시간.
- `stage`, `event`: 이미지 준비, Gemini 생성, 제공자 생성, 결과 저장 단계의
  마지막 진행 상태와 호출 예약·시작·응답·결과 불명 여부.
- `geminiCallsStarted`, `providerCreatesStarted`: 시도 내 누적 시작 횟수.
- Gemini/제공자 호출 상태: `not_started`, `reserved`, `started`, `returned`,
  `result_unknown`.
- 기록에는 원본·프롬프트·이미지·키·서명 URL·제공자 ID·응답 본문·페르소나 이름·
  테넌트 정보가 없다. API에는 이 원장을 조회하는 공개 사용자 경로가 없다.

각 감사 로그 항목은 계속 `operation`, `sequence`, `elapsedMs`,
`geminiCallLimit: 1`, `providerCreateLimit: 1`을 포함하며, 이미지 모델 호출에는
검증된 형식의 `imageModel`과 `aiSource: direct | replit | unconfigured`만 추가한다.

호출의 예약·시작·응답 또는 결과 불명 상태를 같은 시도에서 연결한다.
`call_returned`는 호출이 응답을 돌려줬다는 의미이지 HTTP 성공이나 생성 수락의 의미가 아니다.
제공자 생성 단계 `completed`는 어댑터가 유효한 자원 ID를 얻었다는 의미이며,
아직 학습 중인 Tavus의 최종 `ready`를 의미하지 않는다.
`persistence/completed`는 생성 결과의 라우터 저장 완료다.
`attempt/finished`는 작업 함수 종료이며, 성공 선언이 아니다.
재시작 후 `submitting` 자산을 복구하면 기존 활성 시도를 `result_unknown`으로
표시하고 기존 생성 차단을 유지한다. 기록이 남아도 provider ID를 추정하거나
재시도를 허용하지 않는다.

## 상한과 오류 처리

동일 시도에서 두 번째 Gemini 생성 또는 제공자 생성 호출은
실행하기 전에 차단하고 `call_blocked`를 기록한다.
Gemini SDK의 클라이언트·요청별 자동 재시도는 모두 1회 시도로 고정한다.
제공자 상태 GET은 생성 횟수에 포함하지 않는다.

호출 계수와 허용 상한은 시도 내부에서 관리하며, 로그 전송 실패 때문에
호출을 다시 실행하거나 제공자 ID 저장·정리 절차를 생략하지 않는다.
유료 외부 호출 직전에는 원장에 예약과 시작 상태를 먼저 기록한다. 이 두 기록을
확인할 수 없으면 해당 새 호출을 보내지 않는다. 외부 응답 뒤 원장 업데이트가
실패해도 알려진 provider ID 저장, 기존 quarantine 및 안전 정리는 계속 시도한다.
결과 불명 생성의 기존 조정 차단, 작업권 확인, 명시적 재요청 규칙은 유지한다.

## 보안 및 해석 한계

감사 로그와 DB 원장은 허용 필드만 직접 구성한다. 원본·이미지·프롬프트·키·인증 헤더·
이름·서명 URL·제공자 ID·응답 본문·예외 원문은 전달하거나 기록하지 않는다.
형식이 유효하지 않은 모델 값은 `invalid`로 대체한다.

계수는 앱 호출 시작 증거다. 실제 네트워크 전달, Google·제공자 내부 재처리,
과금 횟수 또는 원격 생성 여부를 독립적으로 증명하지 않는다. `started`는 전송 직전
경계가 기록됐다는 뜻이며, 프로세스가 그 직후 중단되면 실제 전송 여부를 판별할 수 없다.
SDK 자체 재시도는 비활성화하지만 상위 프록시의 동작을 단정하지 않는다.
프로세스 중단 시 DB의 마지막 스냅샷은 보존되지만, 원장 장애 전의 로그·세부 단계,
실제 과금은 복원할 수 없다.
시작만 있고 종료가 없는 호출은 결과 불명이지 0회나 실패 확정이 아니다.
이 기록은 DB의 내구성 있는 멱등성 원장이나 유료 생성 안전 차단을 대체하지 않는다.
기존 기록에 시도 식별자나 호출 계수가 소급 생성되지는 않는다.

## 검증 범위

실제 유료 호출 없이 시도별 저장, 예약/시작 기록의 선행성, 중단 복구의 결과 불명
표시, 원장 쓰기 실패 시 새 외부 호출 차단, 응답 후 원장 쓰기 실패에도 provider ID 저장,
민감정보 비노출을 검사한다.
새 테이블의 운영 스키마는 사용자가 게시할 때 적용되며, API·Worker도 같은 소스로
함께 게시해야 운영 로그와 원장을 사용할 수 있다. 이 작업에서는 운영 마이그레이션,
재게시 또는 새 유료 호출을 수행하지 않는다.
